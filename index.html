WhatsApp API Gateway — lokal, ohne Cloud, ohne Traefik WhatsApp API Gateway — self-hosted, no cloud, no Traefik

🤔 Warum dieser Guide?

Das offizielle OpenWA-Repo ist für Production mit Traefik ausgelegt. Wer OpenWA auf einem Heimserver, NAS oder Pi ohne Traefik betreiben will, läuft in mehrere Fallstricke:

❌
Problem
host not found in upstream "openwa"
nginx.conf erwartet Traefik-Netzwerk → Standalone NGINX
❌
Problem
npm error ERESOLVE / exit code 1
vite@8 inkompatibel mit plugin-react@5 → Node 20 + --legacy-peer-deps
⏱️
Problem
Error 524 / Gateway Timeout
Build dauert >100s → Beide Images per SSH bauen
🔐
Problem
401 Invalid API key
X-API-Key fehlt oder falsch → Richtige Env-Variable + Header
🧱
Problem
NGINX-Standardseite statt Dashboard
Falsches Image / Dockerfile → openwa-dashboard:local nutzen

✅ Voraussetzungen

  • 🖥️ Server mit Docker & Docker Compose
  • 📦 Portainer (optional)
  • 🌐 Externes Docker-Netzwerk highfishNetwork
  • 🔑 SSH-Zugang zum Server
  • 🌍 Zwei Subdomains: Dashboard und API
docker network create highfishNetwork

🔨 Schritt 1 – Images lokal bauen

⚠️ Den Build NICHT über Portainer starten! Der Build dauert länger als das Proxy-Timeout (~100s) und schlägt mit Error 524 fehl. → Einmalig per SSH bauen.

1a – Backend-API bauen

cd /opt
git clone --depth=1 https://github.com/rmyndharis/OpenWA.git openwa-src

docker build \
  https://github.com/rmyndharis/OpenWA.git#main \
  -t openwa-api:local

1b – Dashboard bauen

cd /opt/openwa-src/dashboard
sed -i 's/RUN npm ci/RUN npm ci --legacy-peer-deps/' Dockerfile

docker build \
  --build-arg VITE_API_URL=https://YOURS \
  -t openwa-dashboard:local \
  .

Images prüfen

docker images | grep openwa

🐳 Schritt 2 – Portainer Stack YAML

version: "3.8"
services:
  openwa-api:
    image: openwa-api:local
    container_name: openwa
    restart: unless-stopped
    ports:
      - "2785:2785"
    environment:
      NODE_ENV: production
      PORT: 2785
      LOG_LEVEL: info
      DATABASE_TYPE: sqlite
      DATABASE_NAME: /app/data/openwa.sqlite
      ENGINE_TYPE: whatsapp-web.js
      SESSION_DATA_PATH: /app/data/sessions
      PUPPETEER_HEADLESS: "true"
      PUPPETEER_ARGS: --no-sandbox,--disable-setuid-sandbox,--disable-dev-shm-usage,--disable-gpu
      STORAGE_TYPE: local
      STORAGE_LOCAL_PATH: /app/data/media
      REDIS_ENABLED: "false"
      WEBHOOK_TIMEOUT: "10000"
      WEBHOOK_MAX_RETRIES: "3"
      WEBHOOK_RETRY_DELAY: "5000"
      RATE_LIMIT_TTL: "60"
      RATE_LIMIT_MAX: "100"
      PLUGINS_ENABLED: "true"
      PLUGINS_DIR: /app/data/plugins
      API_MASTER_KEY: "YOUR_SECURE_API_KEY_HERE"
    volumes:
      - openwa-data:/app/data
      # Nur nötig, wenn Plugins Docker-Zugriff benötigen
      - /var/run/docker.sock:/var/run/docker.sock:ro
    healthcheck:
      test: ["CMD", "node", "-e", "require('http').get('http://localhost:2785/api/health', (r) => process.exit(r.statusCode === 200 ? 0 : 1))"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 30s
    networks:
      - highfishNetwork

  dashboard:
    image: openwa-dashboard:local
    container_name: openwa-dashboard
    restart: unless-stopped
    ports:
      - "8085:80"
    depends_on:
      - openwa-api
    networks:
      - highfishNetwork

volumes:
  openwa-data:
networks:
  highfishNetwork:
    external: true

🔄 Auto-Update per Cron

cat > /opt/openwa-update.sh << 'EOF'
#!/bin/bash
set -e
REPO_DIR="/opt/openwa-src"
IMAGE_NAME="openwa-dashboard"
VITE_API_URL="https://YOURS"
LOG_PREFIX="[openwa-update $(date '+%Y-%m-%d %H:%M:%S')]"

echo "$LOG_PREFIX 🚀 Start"
cd "$REPO_DIR"
git fetch origin main
CHANGES=$(git diff HEAD origin/main --name-only | grep "^dashboard/" || true)
git pull origin main
sed -i 's/RUN npm ci/RUN npm ci --legacy-peer-deps/' dashboard/Dockerfile
[ -z "$CHANGES" ] && echo "$LOG_PREFIX ✅ Keine Dashboard-Änderungen." && exit 0
TIMESTAMP=$(date '+%Y%m%d%H%M%S')
docker build --build-arg VITE_API_URL="$VITE_API_URL" \
  -t "$IMAGE_NAME:$TIMESTAMP" \
  -t "$IMAGE_NAME:latest" \
  -t "$IMAGE_NAME:local" \
  "$REPO_DIR/dashboard"
docker restart openwa-dashboard
docker images "$IMAGE_NAME" --format "{{.Tag}}\t{{.ID}}" \
  | grep -v "latest\|local" | sort -r | tail -n +3 | awk '{print $2}' | xargs -r docker rmi
EOF
chmod +x /opt/openwa-update.sh

# Cron (täglich 3:00 Uhr)
echo "0 3 * * * /opt/openwa-update.sh >> /var/log/openwa-update.log 2>&1" | crontab -

🐛 Bekannte Probleme & Lösungen

❌ host not found in upstream "openwa"

Ursache: Dockerfile.traefik nutzt nginx-Upstream der nur im Traefik-Netzwerk auflösbar ist.

Lösung: Im Stack image: openwa-dashboard:local verwenden, kein build:-Block der auf GitHub zeigt.

❌ npm error ERESOLVE / exit code 1

Ursache: vite@8.x ist inkompatibel mit @vitejs/plugin-react@5.1.4.

Lösung: npm ci --legacy-peer-deps im Dashboard-Dockerfile nutzen.

⏱️ Error 524 / Timeout beim Portainer-Deploy

Ursache: Proxy trennt nach ~100s. Build dauert länger.

Lösung: API und Dashboard nie über Portainer bauen. Immer per SSH.

🔐 401 Invalid API key 
docker exec -it openwa env | grep API_MASTER_KEY
curl -H "X-API-Key: DEIN_KEY" https://YOURS/api/health/detailed
❌ NGINX zeigt nur Standardseite

Ursache: Falsches Image oder Build nicht ausgeführt.

Lösung: Schritt 1b erneut ausführen und docker images | grep openwa-dashboard prüfen.

Problem
Error 524 / Gateway Timeout
Build takes >100s → Build both images via SSH

Problem
401 Invalid API key

Problem

Wrong image / Dockerfile → Use openwa-dashboard:local

🐛 Known Issues & Solutions

❌ host not found in upstream "openwa"

Cause: Dockerfile.traefik uses an nginx upstream only resolvable in a Traefik network.

Fix: Use image: openwa-dashboard:local in the stack, not a build: block pointing to GitHub.

❌ npm error ERESOLVE / exit code 1

Cause: vite@8.x is incompatible with @vitejs/plugin-react@5.1.4.

Fix: Use npm ci --legacy-peer-deps in the dashboard Dockerfile.

⏱️ Error 524 / Timeout during Portainer deploy

Cause: Proxy drops after ~100s. Build takes longer.

Fix: Never build API/dashboard through Portainer. Always use SSH.

🔐 401 Invalid API key 
docker exec -it openwa env | grep API_MASTER_KEY
curl -H "X-API-Key: YOUR_KEY" https://YOURS/api/health/detailed
❌ NGINX shows default page

Cause: Wrong image or build not executed.

Fix: Re-run step 1b and check docker images | grep openwa-dashboard.
